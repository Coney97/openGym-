# 独立中文版执行状态

采用独立应用方案：包名 `io.github.coney97.opengym.zh`，首版 `1.0.0`，版本代码 `1`，专用链接 `opengymzh://`。Java 命名空间保留。Beta 和原版通过备份迁移，见 `docs/CHINESE_MIGRATION.md`。

## 已落实

- 独立正式签名保存在 `/workspace/signing/`，私钥和密码不进入仓库。仓库记录公开证书指纹。
- 前端、Capacitor 和 Android 使用一致的中文版身份；首次渲染先加载中文包，原生资源不依赖设备语言。
- 更新入口使用本仓库，仅选择 `zh-CN-v` 稳定系列、精确匹配的 APK 及校验文件；安装前检查包名、更高版本代码和相同签名。
- 专用 NFC、计划分享、小组件和快捷方式链接避免与 Beta 冲突；不申请上游域名的验证权限。
- 设置、管理页面、动态提示、无障碍标签、新建入门计划名称、原生错误、启动错误及备份说明补充中文。外部错误保留状态和原始响应，用户显示中文说明。
- SQLite 队列扩展到界面、原生资源和回退提示、启动及导出说明；迁移前备份，审核绑定两份哈希，每批最多100项，保护用户修改和并发编辑。
- 721项字段已有匹配的语义审核及应用记录，包含150个动作名称、5套步骤、4段介绍及562项界面/原生等文字。其余既有译文没有被自动批准。
- 修正仰卧/俯卧/侧卧、翻举接杠、“空气自行车”“颅骨推举”等明确误译。四类人工参考样本及模型核验工具已准备，不能将参考样本或结构检查当作模型质量通过。
- 静态扫描1090个候选已记录具体分类和保留理由，包含品牌、内部字段、协议、源语言资源键、系统语音匹配配置及原始法律文本。这不是对全部译文的语义批准。
- 审核凭证保存在 `scripts/translation/reviews/`；源码指纹覆盖前端、API、MCP、Android配置及审核资料。发布必须绑定实际 APK、签名、测试日志和 Android 验收。

## 验证与剩余工作

完整前端最近一次成功执行8027项，API800项、MCP138项、Android单元测试50项均通过。新增队列、指纹和模型样本工具共23项测试通过；模型样本工具仅测试了工作流边界，实际模型尚未运行。最后的中文法律说明通过浏览器核查，分享提示另做针对性回归。

前端首次全套运行曾出现一项导览计时失败；停止高负载软件模拟器后，导览30项和完整前端复跑均通过，未删除断言。浏览器手机模式在英文系统区域设置下验证了中文首次启动、新建入门计划、离线记录20公斤×8次、训练量160公斤、保存后重载，以及JSON/含媒体ZIP的单元级迁移兼容性。浏览器记录不代替 APK 验收。

中文名称覆盖5632个动作；步骤覆盖1510个，介绍覆盖87个。仍缺4122套步骤、5545段介绍，共9667项字段；已有译文仍须逐项审校。动作0240和0059的英文名称/介绍与步骤姿势冲突，步骤保持阻塞，不能靠新译文解除。

当前云端没有 `/dev/kvm`。已实际尝试 Android36、35、30 软件镜像：系统能进入启动完成状态，但安装期间出现系统服务中断/重启，或文件传输失去响应。日志保存在 `/workspace/translation-state/evidence/`。安装、中文原生页面、离线训练、重启、通知和两类备份迁移尚无通过的 Android 证据。

官方模型下载地址仍受实际网络规则拒绝。环境草稿包含 `argos-net.com`、`api.github.com` 和 `uploads.github.com`；保存草稿不会自动应用运行策略。没有模型翻译进程冒充运行，也未发布正式标签或最终APK。

## 继续执行

1. 在环境设置审核、保存现有草稿并发布环境；重新连接后核对实际策略及新连接，保持代理和TLS校验。
2. 下载模型，运行 `probe_model.py`，逐项检查单侧、负重、静态保持和拉伸样本，再启动持久队列生成草稿，审校后应用。
3. 继续审校既有译文，核实两项源文矛盾；批次是检查点，不是交付终点。
4. 在可正常运行的云端 Android 设备/模拟器完成真实验收。正式候选构建命令见工作流 README。
5. 所有门槛通过后，才用 `publish_release.sh` 发布 `zh-CN-v1.0.0`，上传 APK、单独校验文件、中文发布和迁移说明，并下载复核。

持久文件与进程不同：状态、依赖和签名需要保留，进程在云机器更换后需要恢复；尚未独立验证全新任务的快照还原。
